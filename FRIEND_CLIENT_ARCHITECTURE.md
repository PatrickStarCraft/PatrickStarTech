# Client rendering architecture

## Static bloom lifecycle

`BloomChunkGeometry` owns immutable per-section vertex arrays. `AddSectionGeometryEvent` runs on the main client thread; it now ignores other levels and captures the active model set before scheduling the worker callback. Section rebuild workers capture model quads without querying Minecraft's mutable model manager. Visible-section submission reads published arrays without touching live blocks or models. Section revisions and a world generation prevent stale worker callbacks from publishing after invalidation; chunk/level unload and resource reload clear old arrays. The bloom target receives the submitted geometry before the post effect. `BloomEventListeners` detects inactive-to-active transitions, clears old snapshots and optional safe-mode builders, and asks the 26.2 `LevelRenderer` to rebuild sections so bloom can appear on already loaded blocks. Active-to-inactive transitions clear those buffers. Resource-load completion reinitializes the post chain and rebuilds active sections through NeoForge's event; the bloom LevelRenderer mixin now only handles target resize. The availability poll uses a client-tick counter instead of a removed GameRenderer field. Activation causes a full visible-section rebuild; measure its cost and visual result in a running client.

## Machine block and renderer boundary

- The registered 26.2 machine BlockStateModel owns static baked geometry: variant models, multipart selectors, formed-part geometry, output overlays, facades, and CTM. Its worker-side collection reads only the passed block state, world snapshot, and ModelData; it never looks up or retains a live MetaMachine. Missing or stale machine state falls back to the definition's default render state.
- Machine variant baking wraps weighted child lists in `MachineWeightedVariants`: normal collection, geometry keys, particle materials, and material flags delegate to vanilla `WeightedVariants`, while CTM discovery walks every weighted descendant instead of sampling only the detector's random choice.
- MachineRenderState is only the immutable model-variant key. `MachineRenderSnapshot`, derived from `BlockEntityRenderState`, now stores the block state, stable machine definition, and descriptor-indexed per-frame payloads. It retains no live machine, world, or baked model reference.
- `MachineBlockEntityRenderer` implements the 26.2 create/extract/submit lifecycle. Extraction is the only stage that reads the live machine; submission resolves the active model generation and consumes the target `SubmitNodeCollector`. `DynamicRender` owns target visibility/bounds plus immutable extraction and submission without inheriting the old `MultiBufferSource`-based `IMachineRendererModel`. Assembly-line, fluid-area, fusion-ring, growing-plant, quantum-chest, and quantum-tank visuals use this target path. Boiler firebox/casing geometry uses `ControllerPartModel` in the static machine model. Shared model registration and machine data publication remain required before generated machine definitions select these implementations.
- The BER resolves its model through `MachineBlockStateModel.find()` at extraction, submission, visibility, and bounds lookup so a `CTMBakedModel` wrapper does not hide the machine descriptor list. It verifies the resolved model's `MachineDefinition` before use.
- `FluidAreaRender` copies the selected fluid, target transparency layer, machine-relative planes, offsets, and per-offset light. Submission draws the copied planes through custom geometry and retains no world reference. Its old immediate callback has been removed; integrated compile `build/friend-client-port-dynamic-snapshot-contract-verify.log` reports 780 global / 432 exact-owned diagnostics, with no diagnostics in the target descriptor paths. No runtime visuals ran.
- `QuantumTankFluidRender` extracts copied fluid identity/tint, amount, capacity, orientation, and gas state, then submits its cut-fluid volume and face label through target geometry/text nodes. The fluid tint comes from `FluidModel.fluidTintSource().colorAsStack`; no `FluidStack` or machine survives into submission. The item-stack renderer remains a separate old path.
- `FusionRingRender` snapshots its active/fade color, oscillation, and orientation, then submits the normal torus plus a bloom-target copy when bloom is active. `GTRenderTypes.bloomLightRing()` owns a position-color pipeline routed to the reloadable bloom source target. Its duplicate legacy per-machine ticket registration has been removed; the shared machine BER must call the snapshot path.
- Generic persistent bloom tickets now submit during `SubmitCustomGeometryEvent` with a selected 26.2 `RenderType`. The manager keeps world/ticket cleanup, camera-relative pose handling, and validity predicates, while each effect submits through the frame collector. `IRenderSetup` now selects a target render type instead of mutating a `BufferBuilder` around direct drawing. The older Fusion Reactor ticket path is gone because its immutable machine snapshot already submits directly to the bloom pipeline. This owned submit path is compiler-clean, but the named static block-layer bridge and safe-mode chunk buffers remain unresolved.
- `QuantumChestItemRender` resolves its item into a target `ItemStackRenderState` during extraction, then submits that frame state with fixed display context, captured orientation, rotation time, and amount-label data. No stored `ItemStack` or machine reaches submit. Its standalone special item-model hookup remains a separate shared item-definition change.
- Dynamic cover text follows the machine BER boundary too. Extraction resolves the cover’s supplied components into positioned formatted lines and records the attachment face; submission applies the prior cover-face transform and draws those lines. The snapshot holds neither a `CoverBehavior`, supplier, nor machine.
- Central monitor rendering now has a target snapshot path for the built-in text/image modules and `rect`/`quad` graphics; nested module placeholders are supported when their renderer implements `IMonitorRenderSnapshotProvider`. GUI-module hit testing/click forwarding runs during extraction; the old GUI texture draw is commented out. Arbitrary registered placeholder renderers still need a shared API snapshot-provider contract because `PlaceholderHandler#getRenderer` wraps them in a legacy callback and hides their implementation type. Keep shared BER registration gated until custom placeholder renderers can participate without live machine/world access during submission.
- `FacadeBlockStateModel` and `CoverBlockStateModel` are composed into target machine models. They read independent immutable facade and ordinary-cover appearance snapshots; their geometry keys and material flags participate in the host model. Generic Simple/I/O covers retain copied overlay IDs, inversion, emissive mode, occupied faces, and plate thickness. The facade model bake resolves the back-plate sprite; dynamic ordinary-cover texture IDs still require the shared atlas directory source. The shared model-data producer remains required.
- `CoverRenderState` now copies ordinary Simple/I/O cover appearance into immutable per-face entries, including occupied-side bits, plate flags/thickness, texture IDs, optional simple `_emissive` companions, and I/O full-bright metadata. `CoverBlockStateModel` is composed into both target machine and pipe models and contributes geometry keys and material flags. Facade covers are excluded here because their independent facade model owns that geometry. The shared machine/pipe publishers still need to supply `COVER_RENDER_STATE`, and the block atlas needs a directory source for `block/cover/` before these dynamic IDs resolve.
- Formed multipart geometry may carry `FORMED_PART_RENDER_STATE`, an immutable controller state/position/orientation/active snapshot. `MachineBlockStateModel` uses it to resolve target controller child models and collects their parts on demand; `BoilerMultiPartRender` supplies the firebox/casing selection through `ControllerPartModel`, replacing its old cached-`BakedModel` cover path. The shared producer must refresh and clear that property with formation/controller changes.
- Minecraft 26.2 makes `shouldRenderOffScreen` renderer-wide rather than per block entity. The machine renderer currently opts in to preserve off-screen effects and filters individual machines in `shouldRender`; measure global-render cost after registration.
- Baked model references belong to the current model-bake/resource generation. Unbaked models resolve dependencies through ModelBaker; reload reconstructs baked machine models and render resources rather than preserving stale sprites or models globally.
- Large-machine culling bounds are supplied through IBlockEntityRendererExtension#getRenderBoundingBox, with the block's default bounds as fallback. Item display is a separate target item-model/special-renderer path and preserves item transforms, stack-derived state, and foil.

## Pipe block models

- `PipeBlockStateModel` implements `CTMModelPartSource` and exposes all center, connection, and restrictor child parts before connected-texture wrapping. Nested weighted definitions use `CTMWeightedVariants`, which preserves the target runtime choice and geometry key while listing every child for detection.
- The registered pipe BlockStateModel selects center, directional connection, and optional restrictor models from copied PIPE_CONNECTION_MASK and PIPE_BLOCKED_MASK. It resolves PIPE_FRAME_STATE from the active 26.2 BlockStateModelSet, collects frame parts with their actual state, and hides frame cull-face quads on sides occupied by covers. When PIPE_PAINTING_COLOR is present, it applies that color to pipe-child tint layers 0/1 and clears their tint indices; unpainted child and frame colors stay on the target block-tint-source path. Its geometry key includes masks, frame state/key, paint color, covered faces, and selected child-model keys.
- PipeModelData must carry immutable frame BlockState, per-face cover model data, facade and ordinary-cover render states, and painting color only when the pipe is painted before the target loader replaces the legacy BakedPipeModel path. The target collector receives the real BlockAndTintGetter and BlockPos; the pipe model does not store a world/position reference. PipeBlockStateModel composes facade planes/back plates and generic cover parts after pipe and frame parts, and includes their geometry keys/material flags. The absent-connection-mask fallback remains center geometry only, with both cover paths composed from their independent snapshots. Shared pipe publication and the atlas directory source remain open.

## Lamp item special model

- `LampItemRenderer` implements the 26.2 `SpecialModelRenderer<BlockState>` path. It copies the lamp state selected from the item stack, collects that state’s current block-state model parts, and submits them with the state’s registered block tint-source layers and foil pass.
- `LampItemRendererType` registers the `gtceu:lamp` special-renderer codec. The target `minecraft:special` item wrapper supplies transforms, foil state, and layer extents; generated lamp item definitions and removal of the legacy item extension/custom-loader wiring are still shared-owner changes.
## Facade cover geometry

- `FacadeBlockStateModel` reads immutable `FacadeRenderState` entries and per-side `COVER_MODEL_DATA` from the host position's ModelData snapshot. Entries carry the facade block state and the old plate/back-side filtering flags; there are no live cover/entity references.
- During collection it resolves each facade block-state model from the currently active `ModelManager` set, wraps the target block view with facade state and child ModelData, then collects and clips its model parts onto the attached face plane. It interpolates the original UV/color grid after clipping and resolves 26.2 `BlockTintSource` colors against the actual facade state/world position.
- The baked facade model retains no block-model references across resource reload. The model-data producer and unconditional facade multipart in generated machine definitions still need common-side wiring. The old standalone facade item loader/display path remains to be migrated separately.

## Facade item model

- `FacadeItemModel` is a target `ItemModel` that bakes a base plate resource at reload time, then appends cached facade block-state quads from the selected item-stack facade state. It keeps the base item transforms, tint sources, foil, particle material, and light properties, and applies the old north-face filter, inset plane, block tint, and UV interpolation to the overlay.
- Its cache is held only by the baked item-model instance, so resource reload replaces cached sprites/quads. It uses item-context tint defaults and an empty block/model-data context; facades whose item appearance requires position-specific model data or a block entity are not covered by this implementation.
- The `gtceu:facade` item-model codec is independent from the `gtceu:facade` block-state-model codec. The target item definition/base asset split and legacy loader cleanup are documented in request 19.
## Shared wiring contract

1. MachineBlockStateModelType#register(RegisterBlockStateModels): the owned mod-bus subscriber registers the target machine codec. Remove the obsolete MachineModelLoader registration from ClientProxy#onRegisterModelLoaders. Register the machine BlockEntityRenderer provider by machine entity type through the target client renderer event.
2. MachineModelBuilder#toJson and generated machine block/model data: emit the registered 26.2 block-state-model type and target variant/multipart codecs; keep machine-state predicates, model rotations/UV lock/weight, nested-model dependencies, dynamic renderer descriptors, replaceable textures, and texture overrides. The target bake resolves and retains dynamic descriptors and override sprite metadata; `MachineBlockStateModel.retextureFormedPartQuads` applies the legacy `side`/`top`/`bottom`/`all` key mapping to formed-part quads. The target BER must call it for that path. Do not apply overrides to ordinary static geometry. The legacy loader field is no longer the target dispatch contract.
3. MetaMachine#getModelData: copy MachineRenderState and the required immutable cover/output/attachment model inputs into NeoForge ModelData; the model worker reads this snapshot using level.getModelData(pos). Do not make chunk meshing dereference the live block entity.
4. MetaMachine#getRenderBoundingBox: delegate to the registered machine renderer's target bounds contract or preserve a documented machine fallback; it can no longer discover a renderer by casting the baked block model.
5. Machine block items: use the target item-model/special-renderer registration and preserve display transforms, stack data, and foil independently from the block-state model.

## Target source evidence and status

The inspected Minecraft patched 26.2.0.88 sources define BlockStateModel.Unbaked, BlockStateModelPart, and BlockModelRenderState. NeoForge 26.2.0.88 defines CustomUnbakedBlockStateModel, RegisterBlockStateModels, DynamicBlockStateModel, and documents that contextual part collection runs on meshing workers and must use the passed level's model-data snapshot. The implementation and shared wiring are still in progress; this contract is not evidence of runtime validation.
